# 政策分析系统移动端适配设计

## 背景与目标

当前系统已经具备基础响应式样式，但移动端仍存在导航长期占据首屏、部分数据表格直接溢出、按钮与分页在窄屏上拥挤，以及图表和详情内容缺少统一小屏约束等问题。

本次适配在不改变后端接口、业务流程和桌面端信息架构的前提下，为现有 Vue 前端建立统一的响应式行为。目标设备范围为宽度 320px 及以上的常见手机、平板和桌面浏览器，并兼顾手机横屏、触控操作与基础无障碍使用。

## 方案选择

采用渐进式响应布局：保留现有页面组件，在应用布局中增加移动导航交互，并以共享样式和少量页面结构调整覆盖各业务页面。

未采用独立移动端组件，因为它会复制页面逻辑并增加长期维护成本；也不引入新的响应式 UI 框架，因为当前需求可以通过现有 Vue 组件和 CSS 完成，引入框架会扩大回归范围。

## 响应式架构

系统继续使用单套 Vue 路由和页面组件，按照三个布局层级适配：

- 大于 820px：保留固定桌面侧栏和宽屏内容区。
- 521px 至 820px：使用顶部栏和可展开导航抽屉，页面内容缩减外边距。
- 320px 至 520px：在上一层基础上进一步压缩卡片留白，表单、操作栏、分页和标题区改为适合单列触控操作的布局。

断点只负责布局变化，不根据设备类型或 User-Agent 分支，确保手机横屏、小尺寸平板和桌面窄窗口获得一致行为。

## 导航与账户区

桌面端继续展示当前侧栏。移动端将侧栏重组为以下部分：

1. 顶部栏固定展示品牌、菜单按钮和当前页面的基本导航入口。
2. 菜单按钮打开覆盖式导航抽屉，抽屉包含全部有权限的页面、当前用户、版本号和退出按钮。
3. 点击导航项、点击遮罩或按下 Escape 后关闭抽屉。
4. 打开抽屉时禁止背景页面滚动；组件卸载或恢复桌面布局时清理该状态。

菜单按钮暴露 `aria-expanded`、`aria-controls` 和清晰的可访问名称。抽屉保留语义化导航标签，键盘焦点样式沿用系统现有规范。

## 页面适配规则

### 公共容器与标题

- 页面卡片宽度不超过视口，窄屏降低内边距和圆角。
- 页面标题、状态标签和操作按钮允许换行，不依赖固定宽度。
- 长用户名、配置值、政策标题、日志和错误文本允许安全断行。
- 使用视口安全区变量处理带刘海或底部手势条的设备。

### 表格与列表

- 所有业务表格放入统一的横向滚动容器，表格保持可读的最小宽度。
- 滚动容器允许触控惯性滚动，并显示清晰边界。
- 不把复杂表格强制改成卡片，以免丢失列之间的对照关系。
- 分页在小屏上自动换行，主要按钮保持足够触控尺寸。

### 表单与操作区

- 筛选网格在小屏上变为单列。
- 操作按钮在手机宽度下按需要占满可用宽度。
- 输入框、选择框和按钮保持至少约 44px 的触控高度。
- 复选框组允许自然换行，避免权限与规则表单横向溢出。

### 详情、分析与图表

- 政策详情头部和元数据在移动端改为纵向排列。
- 政策正文调整字号与行距，并保证长链接和连续字符可换行。
- 分析标签栏允许横向滚动，不压缩标签文字。
- 图表高度根据小屏视口缩减，同时继续通过现有 ResizeObserver 响应容器变化。
- 任务元数据由桌面双列定义列表改为移动端单列信息组。

### 登录页

- 手机端隐藏大幅介绍区域，登录卡片居中并占满安全可用宽度。
- 小屏和横屏降低上下留白，避免软键盘弹出后关键字段不可达。
- 保留现有登录、错误提示和加载行为。

## 数据流与错误处理

本次不修改 API、Pinia 状态、路由权限或页面数据流。移动导航只维护本地开关状态，并监听路由变化和 Escape 键进行关闭。

现有加载态、空状态和接口错误提示继续由各页面负责。响应式样式必须保证这些状态在 320px 宽度下完整显示，不产生页面级横向滚动。

## 兼容性边界

- 支持当前项目构建目标覆盖的现代 Chrome、Edge、Safari 和 Firefox。
- 最小受支持视口宽度为 320px。
- 不承诺支持 Internet Explorer 或禁用 JavaScript 的交互导航。
- 桌面端视觉层级和现有权限行为保持不变。

## 测试与验收

### 自动化测试

- 为移动导航增加组件测试，覆盖打开、关闭、路由选择、Escape 键和无障碍属性。
- 更新页面测试，验证表格滚动容器等必要结构。
- 运行前端单元测试、类型检查、代码检查和生产构建。
- 运行关键 Playwright 场景，验证登录、导航、政策列表与详情、任务中心和分析页面。

### 视口验收

至少检查以下宽度：

- 320px：最窄支持范围，无页面级横向溢出，表格可在自身容器滚动。
- 390px：常见手机宽度，导航、表单和操作区易于触控。
- 768px：平板或手机横屏，使用移动导航且内容空间合理。
- 桌面宽度：继续使用侧栏，现有主要视觉和交互不回退。

### 完成标准

- 所有可访问页面均可在 320px 及以上视口完成主要操作。
- 页面本身不出现非预期横向滚动；复杂表格和标签栏只在其局部容器内滚动。
- 移动导航可通过触控和键盘打开、关闭并完成跳转。
- 桌面布局、权限控制、登录退出和业务数据行为无回归。
- 前端自动化测试、类型检查、代码检查和生产构建全部通过。
