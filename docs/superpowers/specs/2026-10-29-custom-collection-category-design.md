# 采集规则自定义类别设计

## 问题与方案

现有表单和接口只接受已有类别编码，初始化仅提供两类会议且无新增入口，导致其他会议主题无法归档。保留类别外键，在新增、编辑规则表单中提供“新建类别…”和名称输入框。相较只新增一个预置枚举，该方案允许后续主题自行扩展；相较取消类别，保留政策库现有归档、过滤和会议去重语义。

## 数据流与兼容

POST/PATCH 规则接口接受 category_name 或 category_code，二者互斥。新增必须提供其一，PATCH 均省略时保留原类别。名称去除首尾空白，限制 1–256 字符；已有名称直接复用并校验启用状态。新类别 code 由 custom_ 加名称 SHA-256 的前 56 位构成，满足现有 64 字符约束，唯一编码约束阻止并发重名插入；发生并发写冲突时沿用现有 409，可重试保存。

类别创建与规则保存共用 SQLite 事务，后续 URL、触发配置等校验失败时全部回滚。无表结构迁移；旧 category_code 请求、任务快照和文章归档不变。规则接口已有管理员和 CSRF 校验覆盖新入口，不增加单独权限或配置项。

前端仅在“新建类别…”选项下显示名称字段，保存成功从返回的规则对象更新类别选项，再次选择已有类别时不发送遗留名称。无类别时仍可创建首个类别。说明文案区分类别归档与关键词匹配。

## 验证与部署

覆盖新建、同名复用、编辑、缺失/空白/超长/互斥参数、失败回滚、已有类别及权限回归；前端验证新建选项和即时复用。运行后端、前端、构建和冒烟检查，通过既有 Jenkins 流水线发布，沿用线上 config/app.json、service.env 和 data 保留策略，无需调整流水线。
