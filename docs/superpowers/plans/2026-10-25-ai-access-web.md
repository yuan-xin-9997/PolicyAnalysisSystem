# AI 接入网页实施与验收

1. 核验旧 API/MCP、权限、设置页、Cookie/CSRF 和发布日志，列出复用能力与差距。
2. 先编写 `test_ai_management.py`、`ai-access.spec.ts`，确认缺少元数据接口及页面；新增当前用户可选 scope、分页元数据和失败审计，不改数据库。
3. 实现设置子页、菜单、一次性内存密钥对话框、确认撤销、环境地址/示例、工具及客户端兼容说明；验证退出、pagehide 和迟到响应边界。
4. Jenkins 把依赖安装和构建移到停服前，保留预备环境、旧环境和代码备份；测试备份内容与权限、迁移和任务保护。
5. 用 `scripts/verify_ai_web.mjs` 真实 Chromium 完成管理员/普通用户网页操作、实际 API/MCP、权限降低/停用/越权、撤销关联令牌和移动端测试。密钥不输出、不保存 trace/HAR。
6. 独立审查并修复；执行 Linux 后端全量、前端测试/类型/静态检查/构建，更新需求、设计、README、接入及回滚文档。
7. 推送 main，调用 Jenkins API 构建；记录备份、停服窗口和构建结果，从生产 HTTPS 复测页面/API/MCP、历史数据及配置，清理验收凭据并停用测试账号。
