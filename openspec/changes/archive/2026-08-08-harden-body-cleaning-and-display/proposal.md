## Why

抓取入库的政策正文仍混入网页页面装饰信息（如「新华网 > > 正文 2022 12/ 14 11:37:37 来源：新华社」「阅读下一篇： 37 …」「【纠错】 【责任编辑:xxx】」及尾部跟踪 ID），且详情页正文未分段、无首行缩进。根因经实测确认：WebFetch `generic.article` 适配器把正文抽取为**单行空格拼接的纯文本（0 个换行）**，既丢失了原文 `<p>` 段落结构，又把面包屑/来源页眉、编辑署名页脚等装饰内联进正文。现有清洗（按行 `splitlines()`）与详情页分段（按 `\n` 切分）都假定存在换行，因此只在注入了 `\n` 的测试夹具里通过，对真实抓取数据失效。需要从抓取源头恢复段落结构并剥离装饰，使存储正文为纯净、分段的政策文本。

## What Changes

- 在采集链路中新增「按 HTML 段落结构提取正文」：对通过判定的文章，用 WebFetch `fetch_text` 取回原始 HTML，解析正文区域（如 `<div id="detail">`）内的 `<p>` 块为段落文本并以换行拼接，作为入库 `content_text` 的正文来源；`extract_article` 仍负责标题/作者/发布时间等元数据。
- 加固 `_clean_content` 清洗规则，使其对残余装饰（解析后仍可能混入 `<p>` 的编辑署名块「策划：… 出品」「【纠错】」「【责任编辑:xxx】」「阅读下一篇：…」及尾部纯数字跟踪 ID）按段落/标记剥离，并修正 `来源：[^\s]+` 在无空格粘连时吞掉正文段落的缺陷；清洗作用于 `content_hash` 与 `content_text` 之前。
- 详情页正文分段不再依赖原始换行：基于清洗后段落（来自 HTML `<p>` 解析、以换行分隔）渲染独立 `<p>` 块并首行缩进两个汉字宽度；对历史未恢复段落结构的存量数据，分段渲染仍安全（整体作为单段或按句切分兜底）。
- 扩展存量重洗脚本：对已入库的扁平化正文应用新的内联清洗规则剥离装饰；存量政策的真段落结构在其下次重新抓取时由 upsert 自然恢复。
- 测试夹具改用**真实 WebFetch 输出格式**（单行空格拼接、含真实装饰变体如双 `>` 面包屑「新华网 > > 正文」、带空格时间戳「2022 12/ 14」），消除测试与真实数据的格式偏差；同步项目文档。

### Modified Capabilities
- `policy-content-cleaning`: 正文清洗从「按行剥离扁平文本的页眉/页脚装饰」改为「从原始 HTML 正文区域按 `<p>` 结构提取段落、再剥离残余装饰并归一化」，覆盖双 `>` 面包屑、带空格时间戳、编辑署名块、`【纠错】`/`【责任编辑:xxx】`、`阅读下一篇：N …` 及尾部跟踪 ID 等真实装饰变体。
- `policy-database-experience`: 「可读且安全的政策正文详情」需求的段落分段不再以「正文自带换行」为前提，改为基于清洗后段落（HTML `<p>` 解析产出、换行分隔）渲染独立段落块并首行缩进；对无换行的存量正文提供安全兜底分段。

## Impact

- 后端：`policy_analysis.collectors.xinhua`（新增 HTML 段落解析助手 + 加固清洗规则）、`policy_analysis.tasks.runner`（对通过判定的文章额外取回 HTML 并以段落文本作为 `content_text` 来源，`content_hash` 随之基于段落化正文）、`policy_analysis.collectors.webfetch`（复用既有 `fetch_text`，契约不变）。
- 数据：不引入数据库迁移；新抓取政策入库段落化纯正文，存量政策经重洗脚本剥离装饰、真段落结构于下次重新抓取恢复。
- 前端：`PolicyDetailView.vue` 与 `src/styles/main.css` 的段落分段/首行缩进排版基本沿用，补齐对「无换行存量正文」的安全兜底；不引入 `v-html`，保持纯文本安全渲染。
- 测试与文档：新华网适配器/runner 单元测试夹具改用真实输出格式并覆盖新装饰变体与 HTML 段落解析；同步 README、需求与设计说明书。
